# AI利用ログ（CarePact）

提出ドキュメント第8章「AIをどの場面でどう使用したか」の材料。下書き（2026-11-07時点、完成稿は11/9）。

## 1. プロダクトの中でのAI利用

| 場面 | 使い方 | AIに任せなかった部分と理由 |
|---|---|---|
| 退院書類・家族メモの構造化（Issue 7） | Gemini（gemini-3.5-flash-lite、@google/genai、サーバー側 Route Handler 経由のみ）が、書類画像とメモ文から家族の制約・希望・未確認事項を JSON に構造化する | 構造化結果はそのまま保存せず、家族が確認画面で修正・確定してから保存する（AIの出力を鵜呑みにしない設計） |
| 衝突時の代替案の生成（Issue 8） | Gemini が、検証で弾かれたプランへの代替の変更案（最大3案）を文章と変更リストで提案する | 提案は自前の検証エンジンで試し適用→再検証し、`ok=true` になった案だけを「検証済み」として表示する。単位数の計算はAIにさせない |
| デモモードの固定応答（Issue 15） | デモ用の入力がサンプル家族（fixture）と完全一致する場合だけ、構造化と代替案に固定応答を返す | 本番経路と同じ正規化・再検証を通す。固定応答はデモの再現性のための仕組みで、AIの代わりではない |

- APIキーはサーバー環境変数のみ（ブラウザへ配布しない）。呼び出しは認証（Firebase IDトークン）とメンバー確認の後だけ。1ルーム1時間10回までの上限あり。
- 単位数の計算・支給限度額の判定・自己負担の算出は、すべて決定論的な自前エンジン（Issue 5・6）が行い、AIは一切関与しない。理由：介護保険の数字は1単位の誤りも許されず、確率的な出力を混ぜられないため。

## 2. 開発プロセスでのAI利用

| 場面 | 使い方 |
|---|---|
| 仕様設計 | Issue仕様（全16件）を複数AIモデルでクロスレビューし、v1からv5まで5ラウンド改訂した。最終版は別モデルによる最終確認で「登録可」の判定を得てから GitHub に登録した |
| 実装 | 各担当が Codex 等の生成AIで実装し、PRで提出。人（ぽん）が受け入れ条件を1つずつ実物で確認し、担当者が最終確認してマージする2段構え |
| 独立レビュー | 検証エンジン（Issue 5・6）は、実装した側とは別のAIモデルに仕様だけを渡して独立レビューさせ、指摘2件（ショートステイ同日重複時の扱い、算出打ち切り後の記録）を修正した |
| 数値の相互確認 | サンプル家族の期待値は実エンジンで算出したうえで、平林・清武が期待値を見ずに手計算で独立検算した（平林分は全項目一致を確認済み） |
| 提出物の下書き | プロダクト説明ドキュメントと動画台本の下書きを生成AIに作らせ、人側で事実誤認2件（メンバー構成、担当の記述）を検出して修正した |

## 3. 方針

- AIに任せるのは「非定型な入力の構造化」と「文章での提案」まで。数字と判定はコードで保証する。
- AIの出力は必ず別の経路（検証エンジン・人間の検算・別モデルのレビュー）で確かめてから採用する。
